# 天线设计系统的理论与优化方法

> 版本对应：`aster` 源码 `main`（`0b83880`）、守卫 `ansys-aedt-mcp`（`cb834dd`），2026-11-22。  
> 本文描述的是**设计侧系统**（aster / antopt）的理论模型、算法与证据边界；AEDT 求解由守卫系统受管执行。

## 1. 系统定位

本系统要解决的不是“调出一个好看的 S 参数”，而是一个带硬约束、昂贵评估、会产生失败和噪声的**多目标工程设计问题**：

- 设计变量来自参数化几何/结构（尺寸、轮廓、材料、拓扑算子等）；
- 每个候选必须先在 AEDT 中真实建模、求解、导出，才能得到“测量值”；
- 指标是多目标的（带宽、增益、方向图、效率、成本、可制造性……）；
- 约束是硬性的（|S11| ≤ −10 dB、轴向抑制、纹波、拓扑合法性、加工约束等）；
- 单次求解昂贵且有失败率，因此不能把“模型预测”当成“测量结果”。

系统的核心原则是：**优化器只基于真实测量推进；预测只用于提出候选，不进入证据链。**

## 2. 问题的数学形式

设设计变量

\[
x \in \mathcal{X} \subset \mathbb{R}^d
\]

其中每个维度有工程上下界。对每个候选，系统通过受管 AEDT 会话得到测量指标

\[
f(x) = (f_1(x), \dots, f_m(x))
\]

以及归一化约束违反量

\[
g_j(x) \le 0,\quad j=1,\dots,q
\]

实际工程中 \(g_j\) 可以是：S11 是否超过阈值、方向图纹波、轴向电平、拓扑门、成本/时间上限等。约束违反量被归一化为无量纲量：

\[
v(x) = \sum_j \max\left(0, \frac{g_j(x)}{s_j}\right)
\]

其中 \(s_j\) 是各约束的归一化尺度。

优化目标写成（以最大化为例）：

\[
\max_{x \in \mathcal{X}} \; f(x)
\quad \text{s.t.} \quad
v(x)=0,\; \text{topology}(x)\ \text{valid}
\]

对不可行解，系统采用 **feasibility-first**：可行解永远优先于不可行解；在不可行解之间按归一化违反量排序。这样可以保证“一个指标变好但违反硬约束”的候选不会淘汰当前可行最优。

## 3. 系统分层

```
设计 case / 参数化模型 / 结构算子
        │
        ▼
候选择优层：DoE → 多目标优化 / 代理模型 / 物理引导 / 拓扑算子
        │
        ▼
执行层：CampaignRunner → guard 受管 AEDT → 真实求解/导出
        │
        ▼
证据层：测量指标、验收门、Pareto archive、decision log
```

| 层 | 代表模块 | 职责 |
|---|---|---|
| case/建模 | `parametric/`、`cases/`、`topology/` | 参数定义、几何/结构算子、case 注册、拓扑合法性 |
| 优化 | `optimizer/`、`surrogate/`、`physics/`、`doe.py`、`controller.py` | 多目标、代理模型、采集、局部搜索、策略控制 |
| 执行 | `campaign.py`、`executor.py`、`bridge.py`、`worker.py` | 把候选变成真实测量；守卫 run token / 审计 |
| 证据 | `acceptance.py`、`band_acceptance.py`、`pattern_acceptance.py`、`aperture.py`、`metrics.py` | 验收、证据身份、Pareto/超体积 |

## 4. 多目标优化

### 4.1 Pareto 支配与约束支配

对两个可行解 \(x,y\)：

- \(x\) 支配 \(y\)，如果 \(x\) 在至少一个目标上更好，且所有目标不差；
- 不可行解按归一化违反量比较，违反更小者优先；
- 只有可行解进入 `feasible_front`，因此一个“几乎可行但还没过约束”的解不会替换当前可行最优。

系统实现两种主算法：

- **NSGA-II**：快速非支配排序 + 拥挤距离，适合目标少、需要稳定覆盖的常规情况；
- **NSGA-III**：用 Das–Dennis 参考方向替代拥挤距离，适合 Pareto 前沿窄、偏斜、需要保持分布的情况。

两者共享：参数空间适配、约束适配（统一转为 \(g(x)\le0\)）、评估缓存（同一候选不重复付费）、预算计数、generation history。

### 4.2 归档与超体积

系统维护 Pareto archive：保留全部已评估候选，但只把可行非支配解暴露为当前 front。  
二维超体积按固定归一化参考点计算；归一化后目标统一为“越小越好”，hypervolume 曲线可以直观看出：

- 累计 hypervolume 单调不降；
- 当前 generation 的 hypervolume 停滞，是“继续参数搜索收益不大”的信号；
- 如果某个单点极端差，会拉坏经验归一化，因此也可用 case 目标做归一化。

## 5. 代理模型与贝叶斯优化

### 5.1 模型

昂贵的真实求解不可能支撑大规模进化。系统用代理模型在**已测量数据**上学习：

- **Gaussian Process / GPR**：Matern 核，返回均值 \(\mu(x)\) 与预测标准差 \(\sigma(x)\)；
- **RBF**：更便宜的距离型插值，提供不确定度代理；
- 可选 **BoTorch** 后端，用于批量多目标采集。

代理模型统一接口输出均值与标准差，供采集函数权衡探索/利用。

### 5.2 验证与可用性

预测只有在经过验证后才允许参与决策：

- 按几何分组做留出验证（重复几何不能泄漏到训练/验证两侧）；
- 有时间顺序时做前向验证；
- 检查 held-out error 与经验区间覆盖率；
- 数据不足或校准失败时，报告 `unvalidated`，不把训练残差当作验证误差；
- 模型不可用时退回 DoE/直接搜索，而不是盲目相信预测。

### 5.3 采集函数

- **Expected Improvement (EI)**：最大化（或最小化）目标下的期望改进；
- **UCB**：\(\mu(x)+\kappa\sigma(x)\)，通过 \(\kappa\) 控制探索；
- 批量选择：`diverse_batch` 用局部惩罚保证参数空间多样性；
- BoTorch 可选 **qLogNEHVI**（多目标批量超体积）和 qLogNParEGO（带偏好的多目标）；
- 采集前会用“已测量包络”收紧参数范围，防止模型外推到从未测过的区域。

### 5.4 多保真

低保真（粗网格、少 pass、解析估计、粗模型）便宜但有偏。系统采用加性多保真模型：

\[
y_H(x) = \rho\, y_L(x) + \delta(x)
\]

其中 \(y_L\) 是低保真响应，\(\rho\) 是尺度因子，\(\delta\) 是高低保真之间的差异（discrepancy）。低保真样本只用于改进行为/预测，**绝不会冒充高保真测量**。

`coarse_validation.py` 另行提供“实测粗-细筛选”的离线证据门：要求同几何严格配对、独立设计校准/审计、报告节省比例和风险；它只给出局部可用的许可，不代表全种群安全。

## 6. 物理引导的局部优化

### 6.1 灵敏度

系统对已测量指标做中心差分，构造归一化灵敏度矩阵：

\[
J_{ij} = \frac{\partial f_i}{\partial x_j}
\]

每个扰动都是一次真实受管测量，因此灵敏度分析消耗预算，并通过评估缓存避免重复付费。

### 6.2 信赖域局部线性规划

对目标指标的期望改变 \(dy_{\text{target}}\)，求解：

\[
\min_{\Delta x}\ \|J_{\text{target}}\Delta x - dy_{\text{target}}\|^2
\]

约束：

\[
|J_{\text{protected}}\Delta x| \le \varepsilon
\]

\[
\|\Delta x\| \le r
\]

含义：只动目标指标，保护已经通过的指标不被破坏，并且步长限制在信赖域内。  
**得到的只是一个 proposal，必须再跑一次真实测量确认。**

### 6.3 方向图/口径诊断

- 由全空域增益网格积分得到方向性：

\[
D = \frac{4\pi U_{\max}}{P_{\text{rad}}},
\qquad
P_{\text{rad}} = \int U(\theta,\phi)\sin\theta\,d\theta\,d\phi
\]

- 效率：\(\eta = G/D\)（同一方向/峰值处）；
- `aperture.py` 对柱面 rim-slot 复场 CSV 做口径积分、相干性/对称性诊断；它是**离线诊断**，不把 E 场积分冒充辐射功率。

## 7. DoE、结构与拓扑

### 7.1 DoE

在交给优化器前，先用分层/空间填充的 DoE 覆盖参数箱，避免一开始就在局部乱搜。DoE 点用配置哈希做身份，已测量点不会重复排队；分布式调度也复用同一身份，因此崩溃/多机不会重复消耗求解。

### 7.2 结构算子

结构改变不是“LLM 直接改几何”，而是声明式算子：

- 声明适用天线类型、改什么、合法性检查、可能损坏的指标、回滚方式；
- 由 code 执行可验证、可回滚的变更；
- 通过 FamilyManager 维护 family 谱系与算子来源。

### 7.3 何时该动拓扑

当参数搜索不再有效时，触发结构搜索。触发规则是数值化的，而不是感觉：

- 连续 N 轮指标停滞；
- hypervolume 改进低于相对阈值；
- 某个硬约束几乎被所有候选违反；
- 局部灵敏度在信赖域内无法修复失败指标。

触发结果必须带原因，不能只返回一个布尔值。

## 8. 策略控制器

`StrategyController` 是规则状态机，读取：

- 约束状况、停滞/超体积历史；
- 灵敏度/局部搜索是否可用；
- 剩余预算、family 数量、失败率等。

返回“策略 + 机器可读原因”。当前以规则优先，保证可解释；后续可替换/增强为学习型控制器，但“为什么选这个策略”的日志必须保留。

## 9. 成本、风险、鲁棒性

- **成本模型**：在归一化参数空间对已测 `total_seconds` 做 ridge 回归；数据少时退回中位数；用于把一批候选控制在时间预算内。
- **失败风险**：用参数空间近邻的失败率估计候选的局部风险，区分基础设施失败、超时、物理/几何失败；超时是删失观测，不能当作“几何差”的标签。
- **鲁棒性**：给定制造容差窗口，枚举/去重扰动设计，按已测邻居计算 worst-case、mean、spread、yield；优化的是容差内最坏情况，而不是只优化 nominal。

## 10. 验收与证据边界

### 10.1 频带验收

`band_acceptance.py` 的原则：**采样证据不是连续频带证明**。

- 不做插值，不发明缺失频点；
- 要求端点存在、频点覆盖、频点间最大间隙受控；
- 每个支持频点都满足阈值才给 `SAMPLED_PASS`；
- 结果必须标明数据是 `MEASURED` 还是其他来源。

### 10.2 方向图验收

`pattern_acceptance.py` 在保存的球面增益网格上做：

- 赤道环形峰值/纹波；
- 轴向（theta 近 0/180）抑制；
- 指定立体角内的能量占比（用球面求积，而不是从 cut 拼接）；
- 所有统计量返回采样极值和求积结果，不伪造连续方向图。

### 10.3 证据身份

每次真实运行有 run id / config hash / 学习契约身份；推荐、排队、执行、归档必须使用同一身份。预测值标记为 `predicted`，不能写入 measured metrics；守卫也只接受真实求解证据。

## 11. 完整优化流程

```text
1. 加载 case：参数空间、约束、目标、验收规格、拓扑规则
2. 初始 DoE（空间填充），通过 guard 执行真实测量
3. 归档测量结果，计算归一化目标/约束/超体积
4. 循环直到预算耗尽或满足停止条件：
   a. 检查是否触发拓扑/局部搜索/停止
   b. 拟合/更新代理模型，验证可用性
   c. 用 EI/UCB/批量多目标采集提出候选（或 NSGA-II/III 种群）
   d. 约束/边界/已测包络检查
   e. 通过 guard 执行真实测量
   f. 更新 archive、Pareto、成本/风险模型与决策日志
5. 导出 Pareto front、证据与决策记录
```

## 12. 主要不变量

1. **测量优先**：优化器只根据真实测量更新证据；预测只用于候选提议。
2. **约束优先**：不可行解不能替换可行最优。
3. **身份一致**：推荐、排队、执行、归档使用同一配置/运行身份。
4. **可回滚结构**：结构算子是声明式、合法、可回滚的，LLM 不直接改几何。
5. **预算可见**：每次昂贵测量都计入预算；灵敏度和 DoE 也不例外。
6. **守卫边界**：真实 AEDT 操作只走受管会话；预测/模型不能伪造 solver 完成。

## 14. 局限与开放问题

- 代理模型的适用性依赖数据覆盖；外推区域仍必须真实测量；
- 多目标权重/参考点选择会改变“好设计”的定义，需要工程偏好输入；
- 拓扑/结构空间仍是离散算子集合，尚未实现连续拓扑优化；
- 物理局部线性化只在信赖域内有效，步长过大时 proposal 会失败；
- 验收是“采样证据”的保守判定，不等价于全频带/全空域连续证明；
- 真实求解的失败、超时、license/AEDT 状态会污染数据，必须靠证据门和守卫审计隔离；
- 系统是设计侧优化框架，不是 AEDT 沙箱；安全边界在守卫侧。
