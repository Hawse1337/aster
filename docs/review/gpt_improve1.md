HFSS 天线智能设计系统：物理引导与自适应优化能力升级任务书
面向 HFSS 的物理知识驱动型天线智能优化系统
一、项目背景
我目前正在构建一套基于 AI Agent、MCP 和 Ansys HFSS 的天线自动设计与优化系统。
主要研究对象包括：
3D 打印全金属周期结构漏波天线（Periodic Leaky-Wave Antenna）。
金属透镜天线（Metal Lens Antenna），包括适用的透射型及反射型结构。
现有系统可以通过 MCP 控制 HFSS，完成建模、参数修改、全波仿真和结果提取，同时正在尝试引入遗传算法。
但是，目前的 Agent 主要依靠反复修改几何参数和调用 HFSS 来优化性能，存在以下问题：
缺乏对天线电磁机理的有效分析。
不能合理处理带宽、增益、波束方向和副瓣电平等指标之间的冲突。
没有明确区分局部参数优化与整体结构优化。
对参数之间的耦合关系缺乏量化判断。
容易在没有实质性进展时继续重复参数扫描。
缺乏根据历史仿真结果主动调整搜索策略的能力。
在当前结构无法达到目标时，缺少生成和验证新结构的机制。
我希望将系统从“基于 LLM 的自动参数调整工具”升级为“具有物理分析、自适应搜索和结构修改能力的智能天线设计系统”。
核心目标不是用 AI 取代电磁仿真，而是让 AI 与优化算法充分利用电磁理论、历史数据及 HFSS 计算结果，减少无效仿真，提高设计效率和最终性能。
二、整体架构要求
请在现有系统基础上增加四个核心模块：
模块 A：ConstrainedMultiObjectiveOptimizer
带约束的多目标优化模块，解决多个天线性能指标之间的冲突。
模块 B：SurrogateOptimizationEngine
代理模型与贝叶斯优化模块，减少昂贵的 HFSS 全波仿真次数。
模块 C：PhysicsSensitivityAnalyzer
物理引导与参数灵敏度分析模块，帮助 Agent 理解不同几何参数对电磁性能的影响。
模块 D：TopologySearchEngine
结构级搜索与重构模块，使 Agent 不再局限于已有参数的局部调整。
此外，还需要一个统一的调度模块：
OptimizationStrategyController
根据当前设计状态、历史优化结果和计算预算，选择合适的优化策略，并协调上述四个模块运行。
不需要一开始就构建复杂的多 Agent 系统。优先采用模块化 Python 程序，由一个高层 Agent 负责决策。
与现有可靠性模块的关系
此前计划开发的三个可靠性模块：
DesignSpecManager
SimulationGuard
AntennaEvaluator
应当作为本次优化系统的底层基础。
设计规范由 DesignSpecManager 提供；所有真实仿真通过 SimulationGuard 执行；所有性能评价通过 AntennaEvaluator 完成。
新的优化算法不能绕过这些模块直接修改任务目标、运行无保护的求解或者使用未经校验的数据。
如果这些模块尚未完成，请先检查现有项目，明确依赖关系，优先实现必要的最小接口，不要重复开发相互冲突的功能。
三、模块 A：带约束的多目标优化
3.1 设计目的
目前的优化容易出现一个问题：
改善 S11 或带宽后，原本合格的增益、波束方向或者副瓣性能受到破坏。
因此，需要从单一综合适应度优化，升级为真正的多目标约束优化。
3.2 功能要求
首先，将全部设计指标分为两类：
硬约束 Hard Constraints
例如：
指定频带内 S11 不高于规定阈值。
指定频点或频段内实现增益达到要求。
主波束方向误差不超过允许值。
副瓣电平不超过规定值。
满足最小壁厚、最小间隙等制造限制。
优化目标 Soft Objectives
例如：
最大化综合有效带宽。
最大化最差频点实现增益。
最小化副瓣电平。
最大化辐射效率。
最小化体积或重量。
必须明确：硬约束不应仅通过固定权重并入综合评分，否则优化器可能通过牺牲某项硬约束来改善其他指标。
建议优先实现 NSGA-II，并采用可行性优先的约束比较策略。
对于两个候选设计：
两者均可行时，根据 Pareto 支配关系比较。
一个可行、一个不可行时，优先保留可行方案。
两者均不可行时，根据归一化约束违反程度比较，并允许使用适当的多样性保持策略。
未验证或者数据不完整的方案不得被当作有效可行解。
3.3 Pareto 解集管理
建立独立的 Pareto Archive。
至少记录：
每个候选结构的完整参数。
所有性能指标。
可行性状态。
约束违反程度。
Pareto 支配关系。
使用的优化算法。
对应 HFSS 仿真记录。
不允许新的不可行方案覆盖之前已经验证的最佳可行方案。
注意：Pareto Archive 需要同时支持多个目标之间的权衡，而不是强行选择单个最高分设计。
3.4 综合有效带宽
请特别实现综合有效带宽评价。
它不是单纯的 S11 带宽，而是指天线在同一工作频率范围内，同时满足全部已启用电磁性能约束的连续区间。
例如：
S11 达标。
实现增益达标。
主波束方向达标。
副瓣电平达标。
评价时必须按照设计规范明确频率采样条件，不能把未仿真的频点自动判定为满足要求。
不同类型天线可能采用不同的指标组合，必须支持配置。
3.5 推荐技术
可以评估以下 Python 库：
pymoo：NSGA-II、约束处理、Pareto 优化。
NumPy / SciPy：指标计算、归一化及数值处理。
优先复用可靠的开源算法实现，不必自行重新编写 NSGA-II 的所有基础算子。
3.6 验收标准
至少完成以下验证：
新方案仅改善带宽，但违反增益约束时，不得被视为优于已有可行方案。
多个可行方案互不支配时，能够同时保留。
不同量纲的约束违反程度得到合理归一化。
正确区分不可行解与无效数据。
现有遗传算法可以接入统一评价接口。
能导出 Pareto 前沿数据和优化过程记录。
四、模块 B：代理模型与贝叶斯优化
4.1 设计目的
降低每次优化所需的 HFSS 全波仿真次数。
传统遗传算法可能需要大量候选方案评估，而 3D 金属周期结构和透镜天线的全波仿真成本较高。
希望构建数据驱动的代理模型，用较低的计算成本估计候选设计的性能，并主动选择最值得进行真实 HFSS 仿真的方案。
4.2 基本工作流程
采用以下闭环：
从历史数据库读取有效设计及其性能。
判断已有样本是否足够训练代理模型。
必要时使用 Sobol 序列或拉丁超立方采样补充初始数据。
训练代理模型。
评估模型预测误差及不确定性。
在代理模型上进行候选设计搜索。
根据预期改善量、可行概率及模型不确定性选择新候选。
调用 HFSS 精确仿真。
将真实结果写回历史数据库。
更新代理模型，重复优化。
代理模型只能辅助决策。
未经 HFSS 验证的预测结果，不得直接作为最终设计指标或最佳可行方案。
4.3 代理模型选择
请先根据实际设计变量数量、数据规模和变量类型评估适合的模型。
优先考虑：
Gaussian Process Regression（GPR）。
Radial Basis Function（RBF）。
Random Forest 或其他适合混合变量的模型。
必要时再考虑神经网络。
当参数维度较低、真实样本数量有限时，可以优先尝试 GPR。
如果变量较多、包含离散拓扑变量，或者高斯过程训练效果不佳，应考虑其他模型。
不要求一开始集成所有模型。
请将代理模型封装为统一接口，使后续能够替换算法。
4.4 预测对象
建议初期以工程指标为预测目标，例如：
关键频点 S11。
关键频点实现增益。
主波束角。
SLL。
综合有效带宽。
辐射效率。
但需要注意，某些指标在参数变化时可能出现不连续性，例如主瓣切换导致的波束角跳变。
对于此类目标，应考虑改进特征表示、划分模态工作区间，或使用更适合的预测方式，不能盲目假设所有指标都是平滑函数。
后续可扩展至 S 参数曲线、色散特性和方向图特征的预测。
4.5 贝叶斯优化
对于少量昂贵的连续变量优化问题，评估采用 BoTorch 实现多目标贝叶斯优化。
可以研究：
Expected Improvement。
Upper Confidence Bound。
qLogNEHVI。
带约束的候选点选择。
需要合理平衡：
Exploitation：优先搜索预测性能较好的区域。
Exploration：探索模型不确定性较大的区域。
不能始终只选择代理模型预测最优的一个点，否则可能过早收敛到局部区域。
4.6 多保真仿真
请评估建立分级仿真能力：
低成本层：
解析估算。
单元级分析。
经过验证的简化模型。
必要时的粗网格近似。
高成本层：
完整 HFSS 全波仿真。
经过收敛检查的最终结构计算。
低保真数据与高保真数据必须明确标记。
不能将粗网格结果或单元级近似结果直接混入高保真训练标签而不加区分。
尤其需要检查不同仿真层之间的系统性偏差。
4.7 模型可靠性
需要建立以下机制：
训练集和验证集管理。
预测误差评估。
预测不确定性评估。
训练数据来源追踪。
异常样本检查。
代理模型失效判定。
对于不同天线拓扑，优先采用独立代理模型或结构族条件模型。
如果 Agent 改变了单元形状或天线拓扑，不能默认旧模型仍然适用。
4.8 验收标准
可以自动建立训练数据集。
可以训练代理模型并输出误差报告。
能根据不确定性和预期改善量选择新候选。
能通过 HFSS 实际验证候选方案。
不会将预测值冒充仿真结果。
可以在相同仿真预算下，与随机采样和原有遗传算法进行比较。
五、模块 C：物理引导与参数灵敏度分析
5.1 设计目的
让 Agent 不再仅仅知道“某个参数改变以后 S11 变好了”，而是能够判断：
哪些参数主要影响带宽。
哪些参数主要影响波束方向。
哪些参数影响副瓣及口径分布。
哪些参数之间存在明显耦合。
在保护已达标性能的条件下，哪些修改方向更值得尝试。
这是使 Agent 具备物理引导优化能力的重要模块。
5.2 参数灵敏度矩阵
设设计参数为：
x = [x1, x2, ..., xn]
性能指标为：
y = [BW, Gain, SLL, BeamAngle, Efficiency, ...]
建立灵敏度矩阵：
J[i,j] = ∂y[i] / ∂x[j]
初期可以采用有限差分估计。
例如：
J[i,j] ≈ (y_i(x + Δx_j) - y_i(x - Δx_j)) / (2Δx_j)
具体扰动步长应考虑几何尺度、数值误差和 3D 打印分辨率。
需要对输入参数和输出指标进行无量纲化或合理归一化，避免单位差异影响分析。
5.3 敏感度计算优化
不能无条件对全部参数执行完整的中心差分扫描。
应根据 HFSS 预算采用分级策略：
通过物理知识初步筛选重要参数。
对重要参数进行局部扰动。
对不确定参数采用少量试验设计。
必要时使用代理模型估计灵敏度。
对关键结论再通过 HFSS 验证。
需要识别参数之间的交互作用。
当单参数灵敏度无法解释性能变化时，可以尝试局部二阶信息或小规模联合扰动。
5.4 参数耦合分析
请建立参数与性能指标之间的影响关系图。
例如：
参数 A 对波束方向敏感，对匹配影响较小。
参数 B 对增益和副瓣均较敏感。
参数 C 对匹配敏感，但容易破坏漏波分布。
此处关系必须基于实际仿真、模型分析或可靠物理推导，不允许直接使用通用经验代替当前模型的数据。
输出内容应包括：
参数影响强度。
影响方向。
数据依据。
局部有效范围。
不确定性。
明显耦合的参数组合。
5.5 受约束的局部修改
当某些设计指标已经达标时，希望系统能够寻找尽量不破坏它们的参数调整方向。
例如：
当前 S11 和增益均合格，但 SLL 不合格。
系统应当寻找改善 SLL 的参数调整，同时限制 S11 和增益的恶化程度。
建议研究基于局部灵敏度矩阵的约束最小二乘或信赖域优化方法。
可以采用：
min ||J_target · Δx - Δy_target||²
同时约束：
|J_protected · Δx| ≤ ε
并限制：
||Δx|| ≤ trust_region_radius
注意：
以上仅是局部线性近似，不能保证真实 HFSS 响应始终符合预测。
候选方案仍需通过完整性能评价。
如果预测误差持续过大，应缩小信赖域、重新估计灵敏度，或者切换其他优化策略。
5.6 物理诊断接口
要求输出可供 LLM 读取的结构化诊断结果，而非单纯给出数值矩阵。
例如：
{
"current_problem": "SLL exceeds target",
"sensitive_parameters": [
"taper_ratio",
"unit_height"
],
"protected_metrics": [
"S11",
"realized_gain",
"beam_direction"
],
"recommended_strategy": "local_constrained_optimization",
"confidence": "medium",
"requires_hfss_validation": true
}
Agent 应基于诊断结果提出修改理由。
不允许在没有可靠依据时声称某个参数一定能够改善某项性能。
5.7 验收标准
能通过真实或模拟数据计算灵敏度矩阵。
能判断主要敏感参数。
能根据已达标指标建立受保护的局部约束。
能输出可解释的参数修改建议。
能识别局部线性模型失效。
相比无方向的参数扰动，验证是否能够提高单位仿真预算内的有效改善率。
六、模块 D：结构级搜索与自动重构
6.1 设计目的
这是我最希望系统最终具备的能力。
传统遗传算法只能优化预先定义好的几何参数。
如果当前天线结构本身存在瓶颈，继续修改尺寸可能无法满足全部设计要求。
因此，需要允许 Agent 根据电磁分析结果，主动改变天线结构，而不仅仅是修改原始变量。
但结构修改必须可控、可验证、可回退。
6.2 建立结构操作库
不要让 LLM 一开始就自由生成任意复杂的 HFSS 脚本。
优先建立明确的、可执行的结构操作算子。
对于周期漏波天线，可考虑：
调整单元对称性。
在允许位置添加或去除扰动结构。
修改周期加载方式。
修改单元间的耦合关系。
引入纵向渐变结构。
改变辐射单元排列。
修改馈电过渡。
修改终端结构。
在有物理依据时改变辐射机制相关的单元构型。
对于金属透镜天线，可考虑：
替换单元结构族。
调整相位调制单元拓扑。
修改透镜厚度分布。
修改单元排布和采样密度。
调整口径边缘处理。
修改透镜曲面或离散相位分布。
优化馈源位置或馈源与透镜的配合关系。
每种操作都应包含：
适用天线类型。
操作名称。
可修改的结构部分。
输入参数及其范围。
几何合法性检查。
制造约束。
预期影响的物理机制。
可能破坏的指标。
回退方法。
上述物理影响应视为需要验证的设计假设，而不是必然成立的规律。
6.3 结构的统一表达
请评估建立分层的参数化结构描述。
对于漏波天线，可以尝试：
Antenna = Feed + UnitCell + ArrayProfile + Termination
对于透镜天线，可以尝试：
Lens = Feed + UnitCellLibrary + ApertureLayout + SupportStructure
其中：
Feed：馈电结构。
UnitCell：基本周期单元。
ArrayProfile：单元排布及纵向渐变。
Termination：末端处理。
UnitCellLibrary：透镜单元库。
ApertureLayout：孔径单元分布。
SupportStructure：机械支撑结构。
建议使用 Python 类或结构化配置描述结构，而不是依赖自然语言表示几何模型。
需要支持连续变量、整数变量和离散结构选项。
6.4 结构修改的执行流程
Agent 提出结构修改时，应经过以下步骤：
根据性能瓶颈生成结构修改假设。
选择结构操作算子。
创建新的结构版本。
检查几何合法性。
检查 3D 打印制造约束。
进行必要的低成本物理分析。
选择有前景的方案进行 HFSS 仿真。
对比原结构与新结构。
记录修改效果。
决定保留、继续优化或回退。
所有结构版本必须保持独立。
不允许使用未经验证的新结构直接覆盖原始最佳设计。
6.5 区分结构搜索与参数搜索
需要建立结构族（Design Family）的概念。
例如：
Family A：原始对称周期单元。
Family B：非对称周期单元。
Family C：带纵向渐变的周期单元。
Family D：另一种加载或馈电拓扑。
每个结构族具有自己的参数空间。
系统可以分别在不同结构族内部优化参数，再比较不同结构族的性能。
跨结构族比较时，必须使用一致的天线设计目标及评价标准。
6.6 结构升级触发规则
当满足以下一种或多种情况时，系统可以建议启动结构级搜索：
参数优化持续停滞。
当前结构族长期无法满足全部硬约束。
关键性能之间存在难以缓解的冲突。
局部灵敏度表明现有变量无法有效改善目标指标。
代理模型显示当前结构族的可行域很小。
电磁分析发现可能需要改变单元对称性、加载或馈电方式。
不能仅因为一次参数修改失败就直接放弃当前结构。
建议结合历史数据、信赖域表现、Pareto 改善程度以及仿真预算进行判断。
6.7 验收标准
可以用结构操作算子生成新的合法模型。
可以同时管理多个结构族。
可以对不同结构族独立优化。
能检查结构是否满足制造限制。
能在修改失败时回退。
能记录结构修改原因及验证结果。
能证明系统确实搜索了新的结构，而不只是原有参数的重新组合。
七、面向周期漏波天线的专用物理优化流程
我不希望所有天线都采用完全相同的黑箱优化流程。
请针对金属周期漏波天线建立物理引导策略。
7.1 周期结构与空间谐波
对于适用的周期漏波结构，空间谐波相位常数满足：
β_n = β_0 + 2πn/p
其中 p 为周期长度。
当某个空间谐波满足辐射条件时，可由其相位常数估计主波束方向。
需要明确坐标、角度定义及所研究的空间谐波阶数。
7.2 物理特征提取
希望系统能够分析以下物理量：
色散关系。
相位常数 β。
漏波常数 α。
空间谐波辐射条件。
输入反射特性。
辐射效率。
开阻带相关现象。
口径辐射分布。
其中，漏波常数的提取应选择适合当前结构的复模态或有限周期方法，并验证其适用性。
不能仅凭普通无损本征模色散图就认为已经准确获得 α。
7.3 分级优化
建议将漏波天线优化分为三个层次：
第一层：单元级分析
研究周期单元尺寸、对称性、加载方式及其色散特性。
在适用条件下研究主辐射空间谐波以及可能的开阻带问题。
第二层：有限周期结构分析
验证实际反射、泄漏分布、周期数、馈电和终端影响。
第三层：完整天线优化
优化全频带 S 参数、实现增益、波束扫描、SLL 和综合有效带宽。
低层模型的结果只能提供物理线索，不能替代完整天线验证。
7.4 智能诊断示例
例如：
如果 HFSS 结果显示某个频点附近增益明显下降，同时反射增大，而目标波束接近边射方向：
Agent 不应立即盲目增加周期数或调整馈电。
应首先检查：
是否存在开阻带相关现象。
是否存在模态耦合或结构对称性问题。
是否存在馈电或有限长度反射影响。
根据诊断结果，决定优先调整参数、分析单元色散，还是尝试改变单元结构。
要求记录诊断依据，并通过仿真验证。
八、面向金属透镜天线的专用优化流程
透镜天线应根据具体辐射机制分类。
首先识别当前模型属于：
传统折射型透镜。
反射型金属透镜。
透射型超表面或金属透镜。
其他需要专门处理的结构。
不同类型不得直接套用同一套相位补偿公式。
8.1 单元库
对于适用的周期或离散单元透镜，建立单元响应数据库。
保存：
单元几何参数。
工作频率。
反射或透射幅度。
反射或透射相位。
极化特性。
必要时的入射角响应。
结构制造约束。
要求明确周期边界条件、激励设置和相位参考面。
8.2 孔径综合
根据真实馈源场、目标波束方向和透镜几何，计算目标孔径电磁场分布。
对于适用的超表面结构，可先确定目标相位补偿，再从单元库中选择满足相位与幅度要求的单元。
需要考虑：
相位量化误差。
透射或反射损耗。
馈源照明。
相邻单元耦合。
有限孔径效应。
频率色散。
机械结构影响。
8.3 分层优化
建议采用：
单元参数优化。
单元库构建。
目标孔径综合。
完整透镜建模。
HFSS 全波验证。
基于完整仿真结果修正单元分布。
不要一开始就将全部透镜单元尺寸作为彼此独立的高维变量直接交给遗传算法。
对于复杂透镜，可以优先使用区域分组、低维参数化和对称性约束降低搜索维度。
九、OptimizationStrategyController：智能优化策略调度器
9.1 设计目标
Agent 不应始终采用同一种优化方法。
请建立统一的策略调度器，根据当前设计状态选择不同算法。
至少支持：
LOCAL_OPTIMIZATION：局部参数优化。
GLOBAL_SEARCH：全局参数搜索。
SURROGATE_OPTIMIZATION：代理模型辅助搜索。
PHYSICS_DIAGNOSIS：物理与灵敏度分析。
TOPOLOGY_SEARCH：结构级搜索。
9.2 策略选择依据
至少参考：
当前约束满足情况。
当前最佳可行设计。
最近若干轮的性能变化。
Pareto 前沿改善程度。
代理模型预测误差。
参数灵敏度及耦合程度。
当前剩余 HFSS 预算。
是否存在结构级设计瓶颈。
建议先使用可解释的规则和状态机实现。
之后才考虑让 LLM 参与高层策略选择。
9.3 设计迭代规则示例
情况 A：全部硬约束已满足
优先使用局部优化或代理模型，提升次级目标，同时保护已有可行方案。
情况 B：只有少数指标不满足
先分析敏感参数及约束耦合，再开展受约束局部优化。
情况 C：多个指标明显冲突
检查 Pareto 前沿，判断是否存在可行折中方案。
必要时开展全局搜索或结构修改。
情况 D：多轮优化停滞
检查是否为搜索方法、代理模型或结构参数空间的问题。
不要自动认定必须修改拓扑。
情况 E：当前结构族无法找到可行解
在分析证据充分且计算预算允许时，启动结构级搜索。
9.4 每次优化决策必须可解释
每一轮需要记录：
当前最大性能瓶颈。
选择的算法。
选择原因。
将要修改的参数或结构。
期望改善的性能。
需要保护的指标。
预计计算成本。
仿真后是否达到预期。
不要求 LLM 给出冗长推理，但必须产生结构化的设计决策摘要。
十、与现有 MCP–HFSS 工作流的集成
请在原有项目上进行最小侵入式改造。
建议总体流程为：
DesignSpecManager 加载设计目标。
OptimizationStrategyController 诊断优化进度。
选择多目标优化、代理优化、灵敏度分析或结构搜索。
生成候选结构与参数。
验证几何与制造约束。
SimulationGuard 调用 HFSS 完成仿真与数据保存。
AntennaEvaluator 计算全部电磁性能指标。
更新数据库、代理模型及 Pareto Archive。
根据真实结果更新设计策略。
循环执行，直到满足停止条件。
请建立统一接口，例如：
propose_candidates()
analyze_physics()
estimate_sensitivity()
train_surrogate()
suggest_topology_change()
select_optimization_strategy()
evaluate_candidates()
update_design_archive()
接口名称可以根据实际项目调整。
需要特别关注以下问题：
不同算法不得重复维护相互矛盾的评价逻辑。
候选方案必须关联结构族和完整参数。
代理模型预测与 HFSS 真实数据必须严格区分。
任务重启后应能恢复算法状态。
所有算法都必须遵守统一仿真预算。
多个候选不得未经控制就同时修改同一个 HFSS 工程。
十一、算法验证与对比实验
这部分非常重要。
系统完成后，不能只凭 Agent 的主观描述判断是否更智能。
请设计可重复的对比实验。
11.1 基准方法
至少比较：
随机采样或传统参数扫描。
原有遗传算法。
带约束的 NSGA-II。
代理模型辅助优化。
引入灵敏度及物理引导的优化。
引入结构级搜索的完整系统。
建议采用逐模块消融实验，验证每个新增模块的实际贡献。
11.2 测试对象
首先选择一个现有的、能够稳定仿真的周期漏波天线。
随后再测试一个代表性的金属透镜天线。
需要保留原有结构及设计目标作为对照。
11.3 评价指标
至少比较：
达到全部硬约束的成功率。
达到首次可行解所需的 HFSS 次数。
在相同计算预算下的最佳可行性能。
Pareto 前沿质量。
Pareto 超体积改善（适用时）。
总计算时间。
无效仿真比例。
结构级搜索产生的有效新方案数量。
所有方法应使用一致的设计目标、HFSS 设置和公平的计算预算。
随机算法应使用多个随机种子评估，避免仅凭单次实验下结论。
11.4 重点测试场景
测试一：性能冲突
通过修改参数改善 S11，但导致方向图恶化。
检查系统能否识别约束冲突。
测试二：参数耦合
多个参数同时影响增益与副瓣。
检查灵敏度模块能否提供有价值的修改方向。
测试三：代理模型失准
故意引入训练数据稀疏区域。
检查系统是否能够识别不确定性，并通过 HFSS 验证。
测试四：优化停滞
固定结构经过多轮优化仍无法满足目标。
检查策略调度器是否能够识别停滞原因。
测试五：结构重构
在原结构参数搜索无法改善问题时，测试结构操作算子是否能够生成新的可行结构。
测试六：制造约束
候选结构电磁性能良好，但不满足金属 3D 打印限制。
检查系统能否拒绝不可制造设计。
测试七：优化中断恢复
优化过程中 Agent 或 MCP 连接中断。
检查是否能够恢复历史记录和优化算法状态。
十二、推荐开发顺序
请不要一次性将所有功能混合开发。
按照以下阶段逐步推进。
Phase 0：代码审查与基准建立
检查现有代码，明确当前 HFSS/MCP 接口、优化方式、数据保存机制以及可靠性模块的完成情况。
选择一个已有天线工程，建立标准测试流程及基准指标。
先确认整个系统可以重复、可靠地执行仿真。
Phase 1：多目标优化
实现：
Hard Constraints。
Feasibility-first。
NSGA-II。
Pareto Archive。
综合有效带宽评价。
最佳可行方案保护。
优先完成这一阶段，因为它直接解决优化过程中顾此失彼的问题。
Phase 2：代理模型辅助优化
实现：
初始实验设计。
训练数据集构建。
至少一种代理模型。
预测误差评估。
候选点选择。
HFSS 验证闭环。
要求与已有遗传算法进行比较。
Phase 3：物理引导及灵敏度分析

受约束局部优化。

漏波天线专用分析能力。
Phase 4：结构级搜索
实现：
结构族定义。
结构操作库。
混合离散与连续变量搜索。
制造约束验证。
结构版本管理。
新结构与原结构的性能比较。
Phase 5：智能策略调度
整合以上模块，让 Agent 能够根据优化状态自动选择搜索方法。
初期使用规则驱动。
只有在现有规则确实不足时，才尝试更复杂的 LLM 决策或学习型策略。
Phase 6：系统测试与性能对比
完成端到端测试、消融实验及计算成本分析。
十三、开发与执行纪律
不允许为了添加新算法而破坏现有 HFSS–MCP 工作流。
不允许绕过 SimulationGuard 直接执行昂贵仿真。
所有天线性能指标必须由 AntennaEvaluator 根据真实数值数据计算。
不允许用未经验证的代理模型结果冒充 HFSS 仿真结果。
不允许把没有物理依据的结构修改描述为已证实的设计规律。
不允许通过单一指标的改善来认定整个天线设计变好。
结构操作必须具备合法性检查及回退机制。
需要考虑金属 3D 打印的最小壁厚、间隙、公差、残粉清理和支撑结构等实际限制；具体阈值由制造工艺配置提供。
每次优化都要记录完整输入、评价结果、修改理由及计算成本。
请优先使用成熟、可维护的 Python 算法库，不要重复造轮子。
对新的算法功能先使用标准数学测试函数或模拟数据验证，再连接真实 HFSS。
所有算法必须允许设置最大 HFSS 次数、最大计算时间和停止条件。
若现有计算资源不足，请优先实现可运行、可验证的简化版本，并说明高级功能的扩展路径。
不要求所有算法同时上线，应保证每个阶段都能独立运行和验收。
