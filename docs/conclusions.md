## 变量驱动重建（2026-11-12，替换破坏性操作脚本）

### 为什么必须换

旧模型是"破坏性操作脚本"（unite/subtract/move）：第一次 apply 就把 `cone_dn` 并进同轴，
第二次必然失败。四种补丁（unite / subtract / 窄 unite / 备份还原）全部失败，
重建后 `validate_simple` 还会失效。

### 换成了什么

- 参考几何从 `.aedt` 解析成**数据**（`aster/cases/lens28_profiles.json`）：
  碗 9 点、盘 237 点、同轴 5 点、介质 5 点；
- 新算子 `revolve_profile`（Polyline → cover_lines → sweep_around_axis），与参考工程构型一致；
- `aster/cases/lens28_var.py`：碗（含**环领**）、盘、孔阵列全部由参数生成，**不执行 unite**；
- 接地环 = 碗端面上的**凸起领**（半高露出），从根上不需要布尔合并；
- 孔阵列**从 AEDT 面数据量出**：6×φ2.19 @ r=4.2（馈电口耦合孔）+ 12×φ2.53 @ r=16.75，
  每碗各一套（之前按"4+6 个 φ0.6/φ0.8"猜的完全是错的）。

## 本轮（GPT 收尾 + yadof 协作）学到的四件事

### 1. 线程与事件循环是隐式契约

`InProcessBridge` 的每次调用都走 `asyncio.run`，而 MCP 服务端的 AEDT 会话是按事件循环保存的。
在工作线程里配置副本，会让守护"找不到会话"，于是尝试新开一个 AEDT（`port 0`）或拒绝插扫频。
**判据**：同一段代码在主线程成功、在线程里失败 → 先查会话归属，而不是改代码内容。
（P3 最终就是靠"在调用线程配置副本"收口的。）

### 2. 被吞掉的异常会把问题改名

yadof 会话曾用 `except Exception: pass` 包住配置调用，于是真机失败只剩 `E_NOT_CONVERGED`。
改成记录 `setup_error` 后，下一次失败自带原因（`CreateReport`），一轮就修好了。
**规则**：可以不让异常中断流程，但必须把它写进返回值或日志。

### 3. 同一段配置代码存在三份，就一定会漂移

"设 passes → 删扫频 → 建扫频"原先在 manager、yadof 会话、独立脚本各有一份，
差异正是 `InsertFrequencySweep` 的来源。收敛到 `aster.executor.setup_config_code` 后，
顺序问题一次修、三处受益，并用测试钉住"设置在扫频之前"。

### 4. 停滞与失败是两种现象

真机上有两种不同的坏结果：

- **快速失败**（收敛门槛、导出不完整）——有明确错误码，能直接定位；
- **停滞**（hf3d 空转、CPU 几乎不动、40 分钟不结束）——没有错误，只有超时。

后者出现在"directivity 双表达式"和"yadof 会话"两处，至今未定位。
**做法**：给每次真机尝试加 CPU 采样，60 秒内增量 < 5 CPU 秒就判定停滞并终止，
而不是等 1800 秒超时——这轮为此浪费了两次 40 分钟。

### 5. 间歇性失败要按概率处理，不能按个案解释

同一个环径（2.15）的两次运行：第一次 `E_SWEEP_EXPORT_INCOMPLETE`（touchstone 只有 1 行），
换新 campaign 重跑就得到 3.0 GHz / 6.2598 dBi。此前把它解释成"该几何的扫频解不出全带"——**是错的**。

真正的机制是**导出与扫频求解之间的竞态**：导出可能在扫频尚未解完时执行，
单行文件与"设计没有带宽"在数据上无法区分。修法不是给某个候选打补丁，而是：

* 导出结果偏短时**等待并重试**（`execution_policy.touchstone_retries`，默认 1 次，按任务开启）；
* 重试能救回**大部分**但**不是全部**——残余概率必须写进文档，而不是等下次再"重新发现"。

这条经验对其它"偶发红"同样适用：**先判断是概率问题还是确定性问题**，
前者要做重试与统计，后者才该去改几何或算法。

### 6. 策略要放在被继承的地方

重试策略最初写在脚本里，结果被 manager 发布的 case spec **覆盖**，于是"修了却没生效"。
凡是"每次运行都要有的行为"，应当写进 case 的 `execution_policy`/spec，
让所有发布者（脚本、GUI、yadof 会话、批处理）自动继承——这轮的重复 bug 就是没这么做。
